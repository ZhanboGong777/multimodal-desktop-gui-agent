## 语义目标和文字判据

初始方案仍须由真实模型原生给出至少两个不同、可解释且有顺序的语义目标。
不是本地固定 fixture 步骤、caller 整段复制、原语动作清单或同一整体目标换 ID。
允许模型把相关操作合并为一个具有可信可观察边界的语义目标；不要求一项操作
必然独占一个目标，也不能为凑目标数制造虚假的验证阶段。

阶段 `expect_text` 只能逐字选择调用方原始 `expect_text` 成员，阶段 `forbid_text`
只能逐字选择调用方原始 `forbid_text` 成员，保留正反极性。模型不能预测并引入
未知未来页面文字，不能倒置调用方最终必需或禁止的文字。本地校验须独立检查
原生返回串的精确成员关系，不能通过纠错、截断或改写把非法串变成合法串。
传输 JSON schema 与模型可读说明采用同一候选集合；空的一侧也须形成合法
schema，不依靠不合法的空 enum 或静默 transport fallback。

原生 instruction、原生所选判据、验证后 instruction、编译用完整上下文与各自
映射继续分别保留。现在是“模型选择调用方已有谓词作为阶段证据”，不能宣称
模型已生成并验证任意新的 UI 后置条件。

至少两个不同调用方文字谓词，只是在这个受限协议中为两个不同初始阶段提供
判据的必要候选条件，**不是充分条件，也不是通用可观测性定理**。同义、大小写
重复、子串包含，或所有文字只在终页同时出现，都可能无法区分两个实际阶段。
即使 caller 提供三个最终文字，也不能只凭数量宣布支持两个或三个可验证阶段。
不足时应明确停止或澄清，不能伪造后态文字、强行 ready 或降低完成标准。

## 明确未解析标记的前置检查

实现可在模型调用前，拒绝协议明确声明的完整保留标记，例如 `[not specified]`、
`[unknown]`、`<TBD>` 等未解析槽位表示。实际匹配集合、大小写和边界须随源码
冻结并记录；不把普通叙述中的裸 `unknown` / `TBD` 一律当成缺参。命中时保留
原请求、具体本地检查原因、真实 0 HTTP 和 0 输入计数，不虚构模型澄清响应。

这是保守的保留标记检查，不是完整的自然语言歧义检测。无此标记不证明所有
参数都完整；合法模型拒绝或 `needs_clarification` 仍保留并停止，不能改成 ready。
含保留标记但本来意在按字面操作的任务，也可能超出该入口的明确支持范围。

## 不变的执行、完成和发布门槛

- 每个阶段的完整目标与判据必须在首个输入前冻结，可信当前帧须明确显示该
  组谓词尚未满足；已经满足或不能可靠判断不授予新进展。后续阶段不能越过
  失败阶段。
- 每个完成阶段仍须有所属专用窗口内真实、已确认、非 dry-run 的输入，固定
  阶段判据在随后可信新帧通过，并由另一张新帧复核。独立应用事件还须证明
  这些输入确实覆盖所述语义目标；文本匹配和 ready 均不能代替该项核对。
- 调用方 final 原样保留，所有阶段完成后另取新帧独立检查。失败的阶段判据
  不因 final 恰好可见而被追认。模型动作级预测的原始 failed / inconclusive
  继续单列，不改写为 passed。
- 阶段完成台账、剩余任务修订、动作/规划/真实 HTTP/期限共用原预算；没有
  完整回执的派发、取消、超时、证据错误或会计缺口不补成功、不重放已确认
  阶段。字面去重不被夸大为通用语义幂等证明。
- 原 R1/R2 新源真实矩阵、首次 UI 拒绝的恢复、独立事件与每事件唯一回执、
  真实 owner 子退出码、源码前后冻结、日志计数闭合、最终全量回归及逐页
  报告/发布检查均不放松。诊断探针、旧失败或旧 rolling 成功不能替代它们。

验证后只能声明该受限协议在已验收受控窗口任务上的结果。高层不再根据当前
屏幕消歧，纯图形高层理解、任意未来页面文字、任意应用可验证分解或完整自然
语言歧义识别，均不因本次架构修改得到证明。
