# 系统 v2.1.0 发布说明

本版在codex/week6-full-requirements分支实现Week6四项要求：自动分解与顺序执行、错误检测及有界恢复、屏幕感知优化、执行状态监测与日志。使用方法见[README](README.md)，实际结果见[报告](Week6_Robustness_Report.md)。

自然语言CLI采用week6.semantic_subtasks.v6。模型自行提出目标及中间条件；高层分解读取完整任务和有限逻辑反馈，动作层依据新画面定位。操作前已成立的条件不给完成计数，已执行后的失败保留原状态。条件修订须由新原生回复提出，不能修改已经执行的原条件。原消息守卫、未知输入停止、预算和调用方最终条件保留。

失败或输入前被拒绝的原生目标再次原样出现时，程序在原有次数内请求新方案，旧外层重复方案检查保留。恢复反馈仅补充原验证器完整缺失清单之外的原期望文字，缺少核对结果时为null；部分文字匹配不增加完成计数。固定生成提示可建议合并共同产生终点的剩余操作，程序不在本地补写目标。

引号描述与所选可读控件矛盾时，输入前拒绝，并使用有限固定反馈请求模型自行重新选择。只有名称没有可读匹配时，才对已选控件上的ASCII字母OCR拼写保留有限不确定性：4至9字母最多一次编辑，双方至少10字母时最多两次，仅空白差异同样不据此判为矛盾。精确同名竞争控件仍会触发拒绝，程序不替换目标、ID或坐标，也不据此增加完成计数。相近名称的业务含义仍需实际条件核对。

恢复场景包括一次应用审阅拒绝、重新定位后的原生重试及本地提交。两组各两个成功语义目标，0个失败语义目标；恢复发生在第二目标的动作层。首次审阅的动作提示性检查误报通过，原值仍保留。正常场景第二步辅助时效检查超限后仍输入的操作偏差已单列，不能声称所有辅助检查通过。该结果只说明专用窗口上的功能可用，不推导任意应用成功率。完整回归3803项通过，pytest 664.89秒，pytest与Ruff实际退出0；代码及配置前后与冻结记录相同。此前823项运行逻辑检查及本次156项审计器相关检查与完整回归重叠，不相加。

持久化英中Tesseract C API在8帧合成新留出上的文字F1为93.6508%，两批热态整帧中位耗时108.291和109.888毫秒。冷启动较慢，另一个真实单帧没有准确率提升，也没有相对所有基线的速度优势。默认配置保留；持久化路径须显式启用并提供匹配DLL和语言文件。

Python API默认仍为observed_departure，旧rolling_actions与调用方预写--workflow入口保留。真实输入仍逐计划确认，没有--yes。状态由事件更新，长模型调用可能显示stale。

wheel仅包含Python包，配置、CLI和证据从源码使用。模型权重与系统Tesseract DLL不随包分发。安装检查使用已有依赖环境，不宣称干净机器全依赖安装。最终Git提交、源码ZIP、wheel和报告对应字节见外部分发清单。旧v2.0清单、报告与压缩包保留。开发失败分别列在[全部尝试](results/full_requirements_20261028/live_attempts_index_016.json)，包括原完整回归004的真实失败、输入服务超时和模型反复提出附加要求，不把这些失败改判为成功。本轮不进入Week7、不新增训练、不发送外部消息。
