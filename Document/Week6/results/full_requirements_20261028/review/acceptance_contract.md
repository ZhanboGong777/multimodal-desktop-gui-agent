## 1 范围与判定原则

本轮对应大纲中的四项：复杂任务自动拆解及分步执行、错误检测及自动重试、
UI 识别准确率与速度优化、系统监测及日志。使用专用本地窗口验证实现逻辑即可，
不额外要求任意应用通用成功率、跨应用/分辨率综合榜单、竞品比较或复杂 DAG。
有顺序的子任务足以表达本轮任务；若实现选择依赖字段，才检查其引用及无环约束。

四项分别给出可复查证据，不用一个自填的 `requirements_closed=true` 代替验收。
真实窗口成功、CPU 故障验证、保存图探针、性能计时、训练和质量评估分开记录。
本轮不训练模型，不新增消息发送。Root 统一调度所有真实模型和桌面调用。

## 2 复杂任务自动语义拆解与分步执行

### 2.1 实现门槛

1. 用户只给整体任务、原调用方最终 `expect_text`/`forbid_text` 及预算。
   在首次真实输入前，真实模型须返回至少两个不同、可解释的语义子目标及顺序。
   例如选择目标配置、完成审阅、提交结果是语义目标；把完整原指令复制到每个
   `CALLER_GOAL` 容器、把下一动作列表改名或由本地代码固定填入全部子目标，不算
   自动语义拆解。这里不要求每个语义目标含多个点击。
2. 保存完整原请求、实际模型请求/原回复、原生方案、校验结果及 native→compiled
   映射。子目标自己的 instruction 与判据来源可追溯。编译时附加完整 caller
   context 可以保留，但不能抹去模型生成的子目标。
3. 原调用方最终规则不得由模型、编译器、恢复过程或子目标检查替换。最终结果
   仍需一张独立、更新且在正确窗口范围内的新帧检查；模型 `finish`、reason、
   `ready`、派发成功或某个局部检查通过均不能替代它。
4. 每个语义阶段的目标、后置检查和完成依据在该阶段第一次输入前冻结。真正
   完成须有可信新观察满足这些检查；不能在看到失败后改一个更容易的检查来补
   成功。已存在标题、窗口名或始终可见按钮文字本身不构成新进展。
5. 子目标判据还须与所述目标相符。真实验收由独立应用事件/状态核对语义结果，
   不只看通用文本匹配器返回 true。独立状态不进入模型输入，不能提前提供未来
   fixture 画面、隐藏答案、正确坐标或未出现的目标标签来修正模型方案。
6. 允许声明为 advisory 的模型动作级 `expected_result` 保留原始失败，而以预先
   冻结的语义阶段后置条件判断该阶段；两层记录必须分开。语义阶段自身检查失败
   不得因 caller final 恰好可见而被追认 completed。
7. 顺序执行时，仅已验证完成的阶段进入完成台账。失败后可在剩余额度内重新
   观察、修复或重规划**剩余**目标，原方案与失败均保留。修订方案可只剩一个目标，
   不必为凑初始目标数制造新阶段；不能重放已经验证的阶段，不能跨尝试拼接完成。
8. 空方案、重复/不安全身份、重复目标、整体原请求复制、纯原语占位、空判据、
   明显已满足的当前目标或与 caller final 矛盾的判据在输入前拒绝或有限修复。
   模型拒绝/needs_clarification 真实保留，不强制转换 ready。

### 2.2 最少真实窗口矩阵

以下两轮均在**新源码冻结后**、新目录、新窗口初态执行，不沿用017/015的旧成功。
参数组合在模型分解前登记，正常目标与恢复目标不同；不按失败结果偷偷换目标。

| 新轮次 | 整体任务及条件 | 必须观察到的结果 |
|---|---|---|
| R1 正常复杂任务 | 在专用窗口为 ALPHA/GREEN 完成配置、审阅和本地提交；初态尚未满足最终规则 | 输入前的真实原生语义方案≥2目标；依序完成且每阶段有冻结检查和新帧；实际项目/主题/LOCAL COMPLETE 全部正确；fresh caller final 通过 |
| R2 瞬态恢复任务 | BETA/BLUE 的同类整体任务；预先配置首次审阅拒绝一次 | 新的真实语义方案；拒绝被检测，重新观察/规划后完成；已完成配置不重放；每次语义变化有独立已知输入回执；最后同一 caller final 和独立应用终态通过 |

每轮还须：实际 owner `wait()` 子退出码为0、源码前后哈希一致、未知输入0、
完整预算账闭合；所有输入属于已核实 PID/create-time 树及专用窗口；阶段与模型
HTTP/动作计数均可从原件重建。应用的一个双击不能充当两个不同语义转换的各自
输入证明。旧版400ms防重入作为环境条件登记，不计新模型能力提升。

这两轮证明实现能在该受控复合任务上自动分解并执行、以及处理一次真实UI拒绝；
不是两个独立任务族的总体成功率估计，也不证明真实执行器故障恢复。若运行失败，
保留完整失败原件并用新编号记录下一尝试；不把失败当成功，不重发已发生的输入。

## 3 错误检测 重试与状态边界

- 共享动作、规划调用、实际HTTP派发及单调时钟预算覆盖初始分解、修复分解、各
  阶段、格式重试和恢复。使用实际transport事件计数，关闭不可见SDK重试。无新
  输入、无模型请求或被拒绝也如实记录，不互换三类计数。
- 一个语义子目标可以有多轮单动作计划；上层恢复不因此获得新预算。已完成阶段
  不因子运行器重建而重置。临时 planner 限制和包装回调须在正常/异常/取消后恢复。
- 派发意图不是输入回执。进入执行器后没有完整结果须记 unknown/unconfirmed，
  保留已知输入下界并停止自动重放。派发前失败可保持未知0。不可用完成画面补
  推输入来源，也不能救回 cancelled/timed_out/执行失败路径。
- 明确UI拒绝与 ActionResult失败分开：R2可证明前者恢复；后者至少用真实运行器
  走CPU故障替身验证。CPU替身不能被报告为真实桌面成功。

### 最少但充分的独立 CPU 反例

新增独立测试文件 `tests/test_week6_full_requirements_review.py`。只使用离线模型
替身、受控帧、内存执行器和可控时钟，不加载GPU、不截屏、不调用真实模型。
公开API冻结后据其真实接口实现，不猜测尚未落盘的字段。

| ID | 对抗输入或故障 | 必须保持的结果 |
|---|---|---|
| C01 | 初始模型仅一个整体caller容器、重复caller指令或空/重复语义目标 | 不计有效自动拆解；输入前拒绝/有限修复，原回复保留 |
| C02 | 标题/当前已存在文本使第一目标检查预先为真 | 不授新完成/输入credit，不把它算语义进展 |
| C03 | 原生方案试图改caller final、引入越权消息/隐藏目标/额外成功声明 | 原final完整保留；非法方案无输入，不以ready救回 |
| C04 | 子目标后置条件错误，而整体final文本已出现 | 原子目标失败不改判；不得宣称所有语义阶段都完成 |
| C05 | 后续修订用同ID或换ID的相同instruction/checks重放已完成目标 | 拒绝/安全停止；不发生第二次旧阶段输入 |
| C06 | 正常语义阶段完成后下一阶段UI短暂拒绝 | 新观察恢复，仅重试失败/剩余目标，完成台账及共享计数不重置 |
| C07 | 执行器已改变状态后抛异常，无完整ActionResult | unknown增加，已知计数保留下界；无自动重放、无虚构成功 |
| C08 | 派发前窗口身份/几何变化、空屏、旧帧或复用同ID的不同payload | 输入前失败或完成检查不通过；无scope逃逸或假final |
| C09 | 分解/规划耗尽最后HTTP、动作限额或返回晚于deadline | 无后续请求/输入；计数不过额，真实超时/阻止终态保留 |
| C10 | 模型原生动作预测失败，但冻结语义阶段后置条件确实满足 | raw failed保持；仅按既定阶段规则判断，不能改原动作诊断 |
| C11 | cancel/KeyboardInterrupt、日志写入失败或回调异常 | planner限制恢复、动作账不丢；不把错误当0输入或完成 |
| C12 | 根/子状态计数不同、进程消失/PID复用/坏JSON/日志坏行 | 只读监测给出区分诊断，原件不修复；不将stale/finished等同succeeded |

需要依赖字段的实现另加未知依赖/循环反例；只实现严格顺序时检查后续阶段不能
越过失败阶段即可，不为了验收额外强加DAG功能。

## 4 UI 准确率与完整帧速度

### 4.1 对照与数据冻结

由同一台机器、同一份图像bytes、同一CPU资源配置、同一Tesseract/语言数据版本
运行四臂，配置与版本/哈希事先登记：

1. 原生产 `native` 英文 CLI。
2. 原生产 `native` 英中双语 CLI。
3. 原 `screen` 双语算法 + 每帧CLI（准确率等价及加速来源对照）。
4. 候选 `screen` 双语同算法 + libtesseract C API持久实例。

算法差异与transport差异分开归因。C API实例以配置隔离，逐帧设置/清空图像及结果，
不能缓存上次识别文字、坐标或任务答案，线程/实例的所有权须明确。
缺少库、语言资源或初始化失败须显式失败/显式登记回退，不悄悄换成未测方法。

旧六张“留出”已经看过，现作为旧集回归，不能重新称新盲留出。另冻结开发/新
留出图像、完整可见文字及矩形标注、生成种子、字体和哈希；先仅用开发集选择
实现与参数，源码/参数冻结后正式评价新留出一次。新留出至少六个独立帧，覆盖
明暗背景、中文/英文、稀疏/密集与细边框。该小集不是Week7跨应用基准。
任何在正式留出之后的实现变化都重登记新版本，不用同一曝光集假称未见验证。

准确率沿用：空白归一后的完整文字匹配、一对一文字IoU≥0.5，未匹配输出为FP；
矩形一对一IoU≥0.8。完整标注范围、每类分母及TP/FP/FN逐项保存。重复识别只
用于一致性/计时，不能增大独立准确率样本分母。C API与CLI的同算法准确率及几何
等价须先独立核对，不能为匹配旧答案注入标签、图名、预期字符串或坐标。

### 4.2 联合通过门槛

- 在新冻结留出上，候选文字F1严格高于native英文及native双语，精确率和召回率
  不低于对应基线；矩形完整性不退化。候选与原screen双语保持等价，或对差异逐项
  解释并仍满足上述门槛。差异/缺失如实保留，不填0，不丢弃失败帧。
- 候选在**完整帧处理热流程**的配对中位耗时快于native英文、native双语及旧screen
  双语CLI。测量范围是PNG解码→预处理→真实CPU OCR→坐标还原/文本处理→轮廓
  与候选生成，不可只报OCR函数、缓存命中或几何组件时间。
- 冷启动另报：配置加载、持久实例初始化和第一帧完整处理；同时报稳定后热流程。
  准确区分冷/热改善，初始化成本不能消失。不得以candidate热结果对baseline冷
  结果。若只热流程改善，结论明确“稳定运行后的完整帧处理更快”，不称所有冷
  启动、OS截屏、模型推理或整个智能体都更快。
- 不把旧实验的screen“更准但更慢”悄悄改成新结果；新表列日期、源码、配置及
  对照臂，旧值作为历史独立保留。

### 4.3 统计方法

先预热每配置/每帧，保留初始化与预热记录，再在同一frame内交替/预登记随机
顺序运行各配置，避免总是先基线后候选。每帧至少10组有效配对，另以独立第二
批配对复核改善方向；不因较慢而删样本，异常重试也留记录。
使用单调高分辨率计时，保存每一次起止、阶段时间、图像hash、配置、实际结果。
记录中位数、全部有效样本的最近秩p95、逐帧配对差值和相对变化；汇总先按独立
frame看差值，不能把同图多次OCR当成大量独立图像。第二批或逐帧方向不稳定时
报告不确定，不只挑最好一批。可提供以frame为单位的配对bootstrap区间，但小
样本下不将其解释为真实桌面总体分布。Root最后决定预登记运行数，不在结果后
缩减分母。

另用至少一张冻结后的真实专用窗口截图做像素验证，完整帧输入不裁切；若仅标
中心区域，准确率结论只限该区域，整帧精确率仍缺失。保存图识别不是桌面执行
成功。全程不改系统电源设置、不并入模型/GPU计算时间。

## 5 监测 日志和最终交付闭合

- 根状态显示新协议、当前语义目标/阶段、已验证完成目标及累计/剩余共享预算；
  子日志保留逐输入、原计划、观测、检查、恢复及计数。若根不是每输入更新，明确
  事件驱动粒度并链接子日志，不以根0误导实际动作。
- 原子快照、追加事件、PID+create-time身份、真实owner子退出码、取消/unknown/
  blocked/failed/succeeded终态各自保留；观测工具只读、不加载模型、不修坏日志。
- 每个真实成功都能从native语义方案→冻结目标→输入回执→阶段新帧→独立final→
  实际子退出记录追溯。计数/日志写失败不吞已发生输入，不能只杀launcher或重开
  同目录继续拼日志。
- 四项完成需：新语义模式的R1/R2实际成功；对应CPU反例通过；公平新留出准确率
  和全帧性能联合达标；监控日志证据闭合；最终冻结源码的完整回归由Root执行。
  独立代理不得自行跑全量pytest、commit或push。
- 新报告、README、completion和发布说明按真实新结论更新，同时明确旧版完成
  范围和旧证据。所有warning、失败尝试、未知、版本差异、冷启动代价保留；渲染
  并逐页查看新报告，最终DOCX/PDF/打包及Git源码字节独立核验后才宣布本轮完成。

## 6 不能断言的事项

不能从本轮两次受控成功推断任意应用的成功率、开放世界复杂规划、竞争模型优劣、
无人值守稳定时延或完整系统所有场景加速；不能把人工定义工作流说成模型自动
拆解，把模拟说成实机，把UI拒绝说成执行器失败，把caller final可见说成所有
语义阶段均完成。声明的边界与本轮四项要求相容，不影响在该边界内验收实现。
