Week 6 从 `week5-submission` 的提交 `d180710d7efcfdd6930065cdba6abf882a52328f`
开始，开发分支为 `week6-robustness`。目标是完成复杂任务分解、异常恢复、感知优化和运行状态监测，
形成系统 v2.0 及鲁棒性测试报告。目前完成第一项代码增量：失败反馈与恢复过程记录。

## 第一轮改动

原有运行器会在任务未完成时重新观察屏幕、请求计划，但下一次规划没有结构化的失败原因。
现在每次重规划都会收到 `context.recovery`，其中包括最近一轮的失败类型、最多五个动作的结果、
累计动作次数、剩余动作额度和剩余时间。反馈不复制旧坐标、输入文字、模型原文或自由文本错误。

失败类型区分目标解析、视觉定位、动作前后观察、动作执行、步骤验证和任务验证。
允许继续执行的步骤验证失败不会覆盖最终的任务级失败原因。历史失败保留在步骤记录中，
下一轮反馈只描述刚结束的一轮，避免反复引用已经解决的问题。

运行目录新增 `recovery.jsonl`，任务结果新增 `recovery_records`。每条记录对应一次实际恢复尝试，
包含下一轮编号、观察编号、反馈、耗时和结果。`plan_ready` 只表示获得可执行计划，
动作是否执行、任务是否成功仍分别由步骤记录和任务验证决定。
中断发生在日志写入期间时，取消摘要只采用完整记录，并注明损坏行；原始日志保持不变。

重规划沿用原来的次数、累计动作和总时限限制，默认值未提高。
消息任务尝试发送后或草稿检查拒绝后仍会停止重规划。

## 检查方法

安装项目现有依赖后，在仓库根目录运行：

```powershell
$env:PYTHONUTF8 = "1"
python -m pytest -q tests/test_week6_recovery.py
python -m pytest -q
python -m ruff check .
```

Windows 下统一父子 Python 进程的 UTF-8 编码，可避免中文路径在捕获子进程输出时被按 GBK 解码。

新增测试使用模拟观察、规划和执行器，覆盖失败分类、连续重规划、预算反馈、任务验证、
观察及规划异常、超时、三个阶段的中断、日志写入中断和旧结果兼容性。
测试结果见 [第一轮测试记录](Week6_Phase1_Test_Report.md)。

现有 CLI 的 `--planning-attempts` 控制规划轮数，`--max-actions` 和 `--task-timeout`
仍控制整个任务。日志不会触发动作重放。真实桌面验收另行安排；Week 5 的原有十二条测试消息额度已用完。
